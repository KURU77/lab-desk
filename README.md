# 研究デスク

進行中の研究をまとめて管理するアプリです。研究ごとに **概要・先行研究とデータセットの出典・設計図・費用と備品・進捗・これからの予定** を一か所に置き、手持ちの **電子部品や工具の台帳** もあわせて記録できます。

**→ https://kuru77.github.io/lab-desk/**

依存ライブラリなしの `index.html` 1枚。データはブラウザの中（記録は localStorage、画像は IndexedDB）に保存されます。[同期](#端末間の同期google-アカウント)を使うと、自分の Google ドライブのアプリ専用領域にも保存され、パソコン・iPad・iPhone で同じデータを使えます。それ以外の外部には送信しません。オフラインでも開けます（先行研究の [DOI 取り込み](#出典の取り込み)のときだけ、DOI を CrossRef / doi.org に問い合わせます）。

## 画面

| タブ | 内容 |
|---|---|
| 研究 | 研究の一覧（状態で絞り込み）、費用の合計、2週間以内の予定 |
| 設計図 | 実験装置の設計図・回路図・完成イメージ・写真・PDF の一覧。研究や種類で絞り込める |
| 予定 | 全研究の予定を「期限切れ / 今週 / 今月 / それ以降 / 期限なし」でまとめて表示。その場でチェックできる |
| 部品・工具 | 手持ちの部品・工具・計測器の台帳。研究で使っているかどうかに関わらず登録できる |
| 設定 | 端末間の同期、テーマ、バックアップ、CSV 書き出し、サンプルデータ |

### 研究ごとのページ

| | |
|---|---|
| 概要 | テーマ・状態（進行中 / 計画中 / 中断 / 完了）・期間・概要・研究課題・方法・成果物・タグ。次にやることと最新の記録もここに |
| 出典 | **先行研究**：論文・書籍・データシートなど。著者・年・掲載誌・DOI/URL・状態（未読 / 読んだ / 精読済み / 引用予定）・この研究との関係メモ<br>**データセット**：研究に使うデータ。提供元・公開年・版・DOI/URL・ライセンス・取得日（参照日）・形式・規模・手元の保存先・使い方・提供元指定の引用表記。状態（これから取得 / 取得済み / 使用中 / 使用終了）<br>どちらも **一覧をコピー** で引用リストとして書き出せる |
| 設計図 | この研究に紐づいた設計図・イメージ |
| 費用・備品 | かかった費用（区分ごとの内訳つき）と、台帳から紐づけた備品。費用は **単価 × 数量** で合計を自動計算（単価が空なら合計を直接入力）。費用を記録するときに「台帳にも登録」を選ぶと、部品登録と備品への追加まで一度に済む（区分が電子部品・工具・材料なら最初からオン）。備品ごとの **使用済みにする** ボタンで、部品リストの未使用から使用済みに移る |
| 進捗 | 進度（予定の完了率から自動計算、または手動）と、日付つきの研究記録 |
| 予定 | 節目やタスクを期限つきで。超過・7日以内は色で知らせる |

### 部品・工具の台帳

- 分類：マイコン・ボード / センサ / 表示・LED / モーター・駆動 / 電源・電池 / 受動部品 / 半導体・IC / 通信モジュール / コネクタ・配線 / 基板・ブレッドボード / 工具 / 計測器 / 材料・消耗品 / その他
- 型番・総数・単位・保管場所・単価・購入日・購入先・URL・タグ・メモ。単価と数量から合計金額を表示
- 研究の枠に関係なく、持っている部品を **すべて / 未使用 / 使用中 / 使用済み** で切り替えて一覧できる
  - 部品：総数 = 持っている数（使用済みを含む）、使用済み = 各研究で「使用済み」にした数の合計、未使用 = 総数 − 使用済み
  - 工具・計測器・はんだのような消耗品：使っても手元に残る（少しずつ減る）ので「使用中」。使用をやめるか、研究を「完了」にすると空きに戻る
  - どちらの扱いにするかは部品ごとに選べる（初期値は分類で決まり、工具・計測器・材料・消耗品は使用中）
  - 使用済み・使用中の一覧には、どの研究でいつから使ったかが表示される
- **購入履歴**：同じ部品を買い足したら、同じ部品に数を足し、購入日・購入数・単価・購入先・研究を 1 回ずつ履歴に残す
  - 研究の費用を記録するとき、品名から台帳の同じ部品を自動で選ぶ（「新しい部品として登録」も選べる）
  - 部品の編集画面の「追加購入」からも記録できる。総数は購入履歴の合計 ＋ 手動の増減
  - 費用の記録を直すと、つながっている購入履歴も合わせて直る
- **研究の費用から台帳へ**：台帳に入っていない部品・工具・材料の費用があると、研究の「費用」と部品・工具ページに案内が出る。開くと、品名から同じ部品や分類を推測した一覧が出て、まとめて台帳に追加できる（「台帳に入れない」も選べる）。費用の編集画面から 1 件ずつ追加することもできる
- 一覧の **− / ＋** で総数をすぐ増減（手動の増減として記録）。「これ以下で補充」を決めておくと、未使用がそれ以下になったときに赤で表示され、「補充したいものだけ」で絞り込める
- どの研究で使う予定か・使ったかを部品側からも確認できる

## 設計図・イメージ

実験装置の設計図、回路図、配線図、ブロック図、完成イメージ、試作の写真、ホワイトボードの写真などを保存できます。

- **画像・写真・PDF** — ファイルを選ぶか、iPhone ならその場でカメラ撮影。大きな写真は長辺 2200px に縮めて保存します
- **手描きスケッチ** — 方眼紙の上に指や Apple Pencil で描けます。ペン（筆圧対応）・直線・四角・円・文字・消しゴム、5色・3段階の太さ、元に戻す
- **書き込む** — 保存した画像の上に寸法や修正点を書き込み、別の版として保存（元の画像はそのまま残ります）
- 種類（設計図 / 回路図 / 配線図 / ブロック図 / スケッチ / 完成イメージ / 写真 / 資料）・版・日付・タグ・メモつき。研究に紐づけずに置いておくこともできます
- 画像をタップすると全画面表示、もう一度タップで原寸表示。「端末に保存」で元の画像を取り出せます

## 出典の取り込み

先行研究・データセットの追加画面の上の欄に貼って **読み取る** を押すと、書誌が埋まります。

| 貼るもの | 動作 |
|---|---|
| BibTeX | title / author / year / journal・booktitle / doi / url を取り出す（通信なし） |
| DOI（`10.xxxx/...` や `https://doi.org/...`） | CrossRef から書誌を取得 |
| arXiv の URL | arXiv の DOI に変換して CrossRef から取得 |
| データセットの DOI・Zenodo の URL | doi.org から取得（Zenodo・Figshare・Dryad など DataCite の DOI にも対応。版も入る） |

## 端末間の同期（Google アカウント）

設定 →「Google でログイン」で、同じ Google アカウントでログインした端末どうしのデータ（設計図の画像も含む）が同期されます。

- 保存先は自分の Google ドライブの **アプリ専用領域**（appDataFolder）。ドライブの画面には表示されず、このアプリ以外からは読めません。サーバーは使っていません
- 変更は数秒後に自動で送られ、アプリを開いたとき・画面に戻ったときに他の端末の変更を取り込みます。右上の雲マークで状態がわかり、タップすると今すぐ同期します
- 研究・文献・費用・部品・設計図などを **1件ずつ** マージするので、オフライン中に別々の端末で編集しても、同じ項目を同時に書き換えない限り両方の変更が残ります（同じ項目なら後から保存したほうが残ります）。削除も他の端末に反映されます
- ログインの有効期限は約1時間です。切れていたら、アプリを開いたときに自動で取り直します

### 最初に一度だけ：OAuth クライアント ID を作る

Google のログインを使うには、アプリの持ち主の Google Cloud で「OAuth クライアント ID」を発行する必要があります（無料）。

1. [Google Cloud Console](https://console.cloud.google.com/) でプロジェクトを作る（名前は例えば `lab-desk`）
2. **API とサービス → ライブラリ** で「Google Drive API」を有効にする
3. **Google Auth Platform（OAuth 同意画面）** を設定する
   - 対象：外部、アプリ名：研究デスク、サポートメール：自分のアドレス
   - データアクセス（スコープ）：`https://www.googleapis.com/auth/drive.appdata` を追加
   - 対象ユーザー → テストユーザー：自分の Gmail アドレスを追加（テスト中のままで使えます）
4. **クライアント → クライアントを作成**
   - 種類：ウェブ アプリケーション
   - 承認済みの JavaScript 生成元：`https://kuru77.github.io`
   - 承認済みのリダイレクト URI：`https://kuru77.github.io/lab-desk/`
5. 表示された「クライアント ID」（`…apps.googleusercontent.com`）をアプリの **設定 → 端末間の同期** に貼り付けて保存。`index.html` の `GOOGLE_CLIENT_ID` に書いておけば、各端末での入力は不要になります

初回ログイン時に「Google はこのアプリを確認していません」と出た場合は、自分で作ったアプリなので「続行」で進めます。

このリポジトリの `index.html` にはクライアント ID が組み込み済みなので、公開版（https://kuru77.github.io/lab-desk/ ）ではこの手順は不要です。

### ほかの人が使う場合

- 同期のデータは **ログインした人自身の Google ドライブ** に保存されます。アプリの作者を含め、ほかの人のデータを見ることはできません。ログインしなければ、データはその端末の中だけにあります
- Google Cloud のアプリが「テスト中」の間は、**テストユーザーに登録した Google アカウントしかログインできません**（最大 100 人）。使う人の Gmail アドレスを「対象 → テストユーザー」に追加するか、「対象 → アプリを公開」で本番にします（このアプリが使う `drive.appdata` は機密性の低いスコープです）
- ログイン画面には、OAuth 同意画面に設定した **アプリ名とサポートメール** が表示されます

## データの持ち運び

- **設定 → バックアップを書き出す** で JSON を保存、**読み込む** で復元（端末の移動にも）。設計図の画像も JSON に含まれます
- 費用の一覧、部品・工具の台帳は CSV で書き出せます（Excel で文字化けしないよう BOM 付き UTF-8）
